# Iteration Cycles – Shantilly (en)

This document defines a proposal for **weekly or bi-weekly iteration cycles** using the "Shantilly Roadmap" GitHub Project.

## 1. Recommended cadence (4.3)

- **Weekly sprints** (or bi-weekly, if preferred):
  - Sprint start → planning.
  - During the sprint → execution.
  - Sprint end → review + retrospective.

## 2. Using the "Shantilly Roadmap" Project

Suggested columns (already present in the project):

- **Backlog** – ideas and items not yet prioritized.
- **Todo** – items selected for the upcoming sprint.
- **In Progress** – work in progress.
- **Review** – awaiting code review.
- **Testing** – under validation/testing.
- **Done** – completed work.
- **Blocked** – blocked items.

## 3. Sprint ritual

1. **Planning (sprint start)**
   - Review Backlog.
   - Move items to **Todo** for the upcoming sprint.
   - Ensure each item has proper labels/milestones.

2. **Execution (during the sprint)**
   - Move cards through **Todo → In Progress → Review → Testing → Done**.
   - Use **Blocked** for impediments and log the reason.

3. **Review + Retrospective (sprint end)**
   - Compare items in **Done** vs pending.
   - Capture learnings and process adjustments.
   - Update milestones and roadmap if needed.

## 4. Metrics integration

- At the end of the sprint, combine this flow with the **monitoring** doc:
  - See how delivered work correlates with stars, forks, contributors.
  - Adjust next sprint priorities based on these insights.
