# Story E1.4 — ScriptRunner: Execução Declarativa Segura (`run:`)

Como autor de aplicações no Runtime TUI Declarativo,  
Eu quero executar ações `run:` via um ScriptRunner único e governado,  
Para que toda automação externa ocorra de forma segura, rastreável e alinhada ao pipeline EventManager + `on:`.

## Escopo

- Implementar ScriptRunner como único executor de `RunAction` (`run:`) do runtime.
- Localização exclusiva: `internal/runtime/runner/**`.
- Integração estrita com:
  - `ShantillyEvent` + [`EventManager`](internal/runtime/event/manager.go:1),
  - Blocos `on:` e modelo `RunAction` definido em [`docs/architecture/data-models.md`](docs/architecture/data-models.md:175),
  - Layout/Componentes apenas como emissores de eventos (nunca executores diretos).

## Regras Normativas (Invioláveis)

- Entrada:
  - Somente `RunAction` produzido pelo EventManager ao resolver `on:`.
- Execução:
  - Um processo por `UpdateTarget`:
    - Antes de iniciar novo processo para o mesmo `update_target`, encerrar o anterior (SIGTERM → SIGKILL).
- Segurança:
  - Proibido uso de `os.Exit` em `internal/runtime/**`:
    - Permitido apenas em [`cmd/shantilly/main.go`](cmd/shantilly/main.go:1).
  - Proibidas execuções diretas de scripts fora de `RunAction`/ScriptRunner.
- Saída:
  - Resultados retornam como:
    - `ShantillyEvent` normatizado, e/ou
    - Atualizações declarativas no `update_target` (ex.: viewport).

## Critérios de Aceite

- Toda invocação de `run:` no runtime:
  - Passa por `ShantillyEvent` → `EventManager` → `on:` → `RunAction` → ScriptRunner.
- Nenhum componente, LayoutManager ou código legado dispara scripts diretamente.
- Regra 1 processo por `update_target` coberta com testes:
  - Execuções sequenciais,
  - Cancelamento correto,
  - Falhas seguras e rastreáveis.
- Confirmado por gate QA:
  - `docs/qa/gates/1.x.scriptrunner-and-update-target.yml`.
  - `docs/qa/gates/1.x.no-osexit-core.yml`.
