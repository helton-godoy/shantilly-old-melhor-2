# Story 2.1: Advanced Form Types & Validation

## Status

Ready for Review ✅

## Story

**As a** shantilly user,
**I want** to use advanced form field types (numeric, date, file) with validation capabilities,
**so that** I can create more sophisticated and reliable forms with better data quality.

## Acceptance Criteria

1. AC1: Usuários podem definir campos numéricos no YAML e recebem feedback imediato para entradas não-numéricas.
2. AC2: Usuários podem configurar limites mínimo/máximo para campos numéricos e são alertados quando excedem esses limites.
3. AC3: Usuários podem definir campos de data com formato consistente e são orientados sobre o formato correto.
4. AC4: Usuários podem configurar campos de seleção de arquivo com filtros de tipo e são alertados sobre arquivos incompatíveis.
5. AC5: Usuários podem marcar campos como obrigatórios e são impedidos de submeter formulários com campos vazios obrigatórios.
6. AC6: Usuários recebem mensagens de erro claras e específicas em português quando inserem dados inválidos.
7. AC7: Usuários não conseguem submeter formulários com erros de validação, sendo guiados para corrigir os problemas.
8. AC8: Usuários com dados inválidos recebem sugestões específicas de como corrigir os erros.
9. AC9: Campos obrigatórios são visualmente destacados na interface para orientação clara.

**Extended Field Structure:**

```go

    Type string `yaml:"type"`

    Max        *float64 `yaml:"max,omitempty"`

    MinLength  int      `yaml:"minLength,omitempty"`
    MaxLength  int      `yaml:"maxLength,omitempty"`
}
```
