# Story 1.6: Submissão e Saída JSON

## Story

**Como um** desenvolvedor que integra com o runtime TUI declarativo,
**Eu quero** que o runtime, ao receber o evento de submissão declarativo (`form:submit`), produza um JSON estruturado no stdout com base no YAML único,
**Para que** scripts externos possam consumir resultados sem acoplar-se a implementações internas de formulário.
**Pré-requisitos:** Story 1.5

## Acceptance Criteria

1. AC1: A biblioteca `huh` DEVE ser configurada para permitir submissão do formulário (tipicamente após o último campo ou via botão implícito).
2. AC2: Após a submissão, a aplicação `bubbletea` DEVE ser terminada.
3. AC3: Os valores inseridos em cada campo do formulário DEVEM ser coletados.
4. AC4: Os dados coletados DEVEM ser formatados como um objeto JSON, onde as chaves são os valores `key` definidos no YAML para cada campo.
5. AC5: O objeto JSON resultante DEVE ser impresso no `stdout`.
6. AC6: A TUI DEVE ser limpa da tela antes da impressão do JSON.

### Data Models

**FormConfig Structure:**

```go
// internal/config/config.go
type FormConfig struct {
    Title  string  `yaml:"title,omitempty" json:"title,omitempty"`
    Fields []Field `yaml:"fields" json:"fields"`
}

type Field struct {
    Key         string   `yaml:"key" json:"key"`
    Label       string   `yaml:"label" json:"label"`
    Type        string   `yaml:"type" json:"type"`
    Placeholder string   `yaml:"placeholder,omitempty" json:"placeholder,omitempty"`
    Value       string   `yaml:"value,omitempty" json:"value,omitempty"`
    Options     []string `yaml:"options,omitempty" json:"options,omitempty"`
    Limit       int      `yaml:"limit,omitempty" json:"limit,omitempty"`
    Affirmative string   `yaml:"affirmative,omitempty" json:"affirmative,omitempty"`
    Negative    string   `yaml:"negative,omitempty" json:"negative,omitempty"`
    Title       string   `yaml:"title,omitempty" json:"title,omitempty"`
    Detail      string   `yaml:"detail,omitempty" json:"detail,omitempty"`
}
```
