# Story 1.2: YAML Configuration Parsing

## Story

**Como um** autor de aplicações no Runtime TUI Declarativo,
**Eu quero** que o binário `shantilly` parseie o YAML único recebido via `stdin` (ou `--file`) em um `AppConfig` v2.0 contendo `Layout`, `Components`, `On`, `Run` e `Security`,
**Para que** o `LayoutManager` (E1.1) e os demais motores (EventManager, ScriptRunner, Modal Stack) tenham uma base declarativa única e consistente, substituindo o modelo legado centrado em `FormConfig`.

## Acceptance Criteria

1. AC1: DEVE existir uma struct raiz `AppConfig` (pacote `pkg/declarative`) representando o YAML único (layout + components + on: + run: + security), conforme arquitetura v2.0.
2. AC2: O CLI `shantilly` DEVE usar `gopkg.in/yaml.v3` para carregar `AppConfig` a partir de `stdin`/`--file` e repassar este modelo ao runtime (incluindo `LayoutNode` usado pelo `LayoutManager`).
3. AC3: Em caso de falha de parsing/validação, o binário DEVE emitir erro claro em stderr e encerrar com código != 0 (conforme NFRs), sem comprometer as invariantes de segurança.
4. AC4: A implementação NÃO DEVE introduzir novos acoplamentos normativos ao modelo legado `FormConfig`; qualquer uso residual é explicitamente Legacy e restrito ao `FormComponent`.
5. AC5: O sucesso do parsing DEVE ser a base para as Waves seguintes (LayoutManager, EventManager, ScriptRunner, Modal Stack), garantindo rastreabilidade E1.1–E1.5.

### Data Models

**YAML Configuration Structure:**

```go
// internal/config/config.go
type FormConfig struct {
    Title  string  `yaml:"title,omitempty" json:"title,omitempty"`
    Fields []Field `yaml:"fields" json:"fields"`
}

type Field struct {
    Key         string   `yaml:"key" json:"key"`
    Label       string   `yaml:"label" json:"label"`
    Type        string   `yaml:"type" json:"type"`
    Placeholder string   `yaml:"placeholder,omitempty" json:"placeholder,omitempty"`
    Value       string   `yaml:"value,omitempty" json:"value,omitempty"`
    Options     []string `yaml:"options,omitempty" json:"options,omitempty"`
    Limit       int      `yaml:"limit,omitempty" json:"limit,omitempty"`
    Affirmative string   `yaml:"affirmative,omitempty" json:"affirmative,omitempty"`
    Negative    string   `yaml:"negative,omitempty" json:"negative,omitempty"`
    Title       string   `yaml:"title,omitempty" json:"title,omitempty"`
    Detail      string   `yaml:"detail,omitempty" json:"detail,omitempty"`
}
```
