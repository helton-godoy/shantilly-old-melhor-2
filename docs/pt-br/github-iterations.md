# Ciclos de Iteração – Shantilly (pt-BR)

Este documento define uma proposta de **ciclos de iteração semanais ou quinzenais** usando o GitHub Project "Shantilly Roadmap".

## 1. Cadência recomendada (4.3)

- **Sprints semanais** (ou quinzenais, se preferir):
  - Início da sprint → planning.
  - Durante a sprint → execução.
  - Fim da sprint → review + retrospectiva.

## 2. Uso do Project "Shantilly Roadmap"

Colunas sugeridas (já presentes no project):

- **Backlog** – ideias e itens ainda não priorizados.
- **Todo** – itens selecionados para a próxima sprint.
- **In Progress** – trabalho em andamento.
- **Review** – aguardando revisão de código.
- **Testing** – em validação/testes.
- **Done** – concluído.
- **Blocked** – impedimentos.

## 3. Ritual por sprint

1. **Planning (início da sprint)**
   - Revisar Backlog.
   - Mover para **Todo** os itens da sprint.
   - Garantir que cada item tem labels/milestone adequados.

2. **Execução (durante a sprint)**
   - Mover cards entre **Todo → In Progress → Review → Testing → Done**.
   - Usar **Blocked** para itens travados e registrar o motivo.

3. **Review + Retrospectiva (fim da sprint)**
   - Verificar o que ficou em **Done** vs pendente.
   - Registrar aprendizados e ajustes de processo.
   - Atualizar milestones e roadmap, se necessário.

## 4. Integração com métricas

- Ao final da sprint, combinar este fluxo com o doc de **monitoramento**:
  - Ver como o volume de trabalho entregue impacta stars, forks, contribuidores.
  - Ajustar prioridades para a próxima sprint com base nesses dados.
